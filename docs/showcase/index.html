Project a glanceable HUD of your FoundryVTT D&D session onto Even Realities G2 AR glasses (576 × 288, 4-bit greyscale phosphor green), driven by tap / swipe / double-tap gestures from the Even R1 smart ring. Foundry shows a QR — on your own screen, or on the GM’s — you scan it, and your character streams straight to the glasses — no server to run. Eyes on the table, not on a laptop.

◈ pillars

✨ Four ideas, no magic.

Deterministic by design — every action is an explicit gesture → tool → Foundry. Nothing to host: Foundry itself serves the glasses app.

▤

Glanceable HUD

Reads like the paper 5e sheet: portrait · AC shield and HP box · square map · ability and save pages · one context panel. Zone boundaries never move, so you learn where to look once.

⌬

Gesture-driven

R1 ring: tap for actions, swipe to move the cursor, double-tap to go back (exit at root). Long-press opens a shortcuts menu as an extra — never the only path.

✦

Foundry as truth

Every action goes through Activity#use() with all rules, hooks, MidiQOL, advantage / disadvantage. The DM keeps full veto power.

≣

Zero infrastructure

The glasses app ships inside the Foundry module and is QR-sideloaded same-origin. The player’s own Foundry client is the projector while online, a GM is the fallback; every payload on the relay is AES-256-GCM sealed. No bridge, no Docker.

▰ project invariants

🛡️ Four rules. Non-negotiable.

Every PR, every audit, every release must satisfy them. They're constraints, not guidelines — ratified in §0.1 of the spec as the contract between today's design and tomorrow's implementation.

⌬

INV-1 · Layout integrity

Formatting and layout are dynamic and always perfect. Frame corners, dividers and columns align to the character in every state — HP 7 / 70 / 700, names from 4ch to 16ch, Italian to English — never misaligned for any reason. Snapshot tests + Box/TextRun render contract.

⌥

INV-2 · Online cross-validation

Every technical claim cites a canonical upstream source — Even Hub docs and changelog, foundryvtt.com, dnd5e, the npm registry. Re-verified before each version bump and every GO/NO-GO gate. Drift is classified, fixed and logged.

▤

INV-3 · Documentation coherence

Spec / README / showcase are always coherent and updated in the same commit for any cross-cutting change — version, fps target, phase count, hardware spec, locale set. No half-updated states. Cross-reference integrity is a hard gate.

≣

INV-4 · Code quality

Code is clean, optimized, documented — and zero dead or unreachable code tolerated. Biome + TS strict + Vitest coverage gate enforce in CI. // TODO without an issue/ADR link fails the build. JSDoc/TSDoc on every public API. Hot-path benchmarks gate regressions.

▣ pairing

📦 One module, one QR — pair your own glasses.

Install the Foundry module (manifest URL) — it also serves the glasses app. Since ADR-0017 the glasses belong to the players: the GM enables them once (Abilita occhiali per i giocatori creates a “<Player> (G2)” user per player and seals its password for that player’s public key), then each player opens Pair my glasses (Associa i miei occhiali) in their own Foundry and scans the QR with the Even Realities App. While the player has Foundry open, their client is the projector and actions run as that player; otherwise an online GM that holds the device key takes over. Players without Foundry at the table are still paired by the GM with Pair G2 glasses (Associa occhiali G2, also on right-click in the Players list). Foundry just needs valid HTTPS reachable from the phone. Guides: the project wiki (Italian) and the setup guide.

The GM dialog below (Pair G2 glasses) pairs a player on their behalf — for players who don’t have Foundry open at the table. Single-use QR, 5-minute expiry, connection checks and the paired-device list with Revoke.

⌬

Single-use QR

The QR carries the page URL plus a fragment (user, password, device key) that never reaches the server. On first connect the projector rotates the device key, so a scanned QR never works twice (a GM-generated QR also expires after 5 minutes). A 16-character manual code is the fallback.

▤

A dedicated “(G2)” user

One Foundry user per player, role Player, owning only what the player owns. Every action runs through dispatchTool on the single elected projector (ADR-0011 / ADR-0017) and is audited. The GM can revoke a device or regenerate its password at any time.

⊟

Sealed on the relay

Foundry relays module messages to every client, so every payload is AES-256-GCM sealed with a per-device key held only by the phone and the projector clients; passwords and keys travel sealed for each recipient’s ECDH public key. Other clients see ciphertext.

    ▥ scheda da tavolo
    
👓 Your character sheet, on the glasses.

    
The HUD reads like the paper 5e sheet and D&D Beyond. Five fixed zones on the 576 × 288 canvas: A portrait 144², B header 288 × 144 (AC shield, HP box + temp, INIT · SPD · PROF, ● Action ▲ Bonus ◆ Reaction, conditions, ▲ YOUR TURN), C square map 144² centred on your token — the scene’s original art, pixelated (see below), ≤ 1 fps, D sheet 288 × 144 (Abilities · Saves & Skills, death saves at 0 HP) and E the context panel — the only zone that reacts to input. Zones A–D are drawn by our own 4-bit pixel renderer and bitmap fonts (the firmware font has no D&D glyphs); budget 4/4 images + 4/8 text, no page rebuild during play. Real simulator screenshots below (Italian UI; the map shows the pixelated scene art of the demo crypt); full design in docs/design/g2-sheet-ux.html.

    

      
      
      
      
    

  


  
  

    ⌥ architecture
    
🏗️ No bridge. Foundry is the server.

    
The glasses app is served by Foundry at /modules/evenfoundryvtt/g2/ and loaded by the Even Realities App from the pairing QR. Same origin means no CORS, no whitelist, first-party cookies (Foundry v13 and v14). The projector — the player’s own Foundry client while online, otherwise a GM holding the device key — computes dnd5e derived data, answers snapshots, pushes deltas and is the only client that executes that device’s actions. Decision records: ADR-0016 · ADR-0017.


    

      
    

  


  
  

    ⊞ map · arte originale pixelata
    
⚡ Your battle map, pixelated for 16 greens.

    
Zone C shows the scene’s original art — background, tiles and token art — not a schematic. The projector’s scene reader sends only compact scene data (MapSnapshot: grid, walls, tiles, visible tokens, image URLs); the phone fetches the pictures same-origin from Foundry and renders the square in plain, deterministic TypeScript (ADR-0018). Darkness outside your token’s sight means the map never reveals rooms your character can’t see. Inspired by the Doom-on-exotic-devices pattern and ditherpunk.

    ▰ frame rate
    
⚡ Six layers, 5 to 15 fps.

    
BLE bandwidth is the bottleneck on a 4-bit greyscale phosphor display. This optimisation stack was designed for the v0.9 full-screen raster (5 fps committed, 15 fps stretch). The v0.12 sheet-layout map needs far less: one 144 × 144 image, ≤ 1 fps, changed tiles only, paced to the SDK's 100 ms image limit.

    🌐 multilingua
    
⚙️ Locale follows Foundry. Override on the glasses.

    
Internationalization is wired in from the MVP — the locale auto-detects from game.i18n.lang in Foundry and broadcasts at handshake; the player can override it directly from the glasses without touching the world setting. Catalogs live in Foundry (dnd5e + module languages), the G2 carries no strings of its own. See §7.16 of the spec.

▶

        
Source of truth: Foundry

        
Locale is read from game.i18n.lang at handshake. Catalogs come from dnd5e (en/de/es/fr/it/ja/ko/pl/pt-BR/ru/zh-CN) and the evenfoundryvtt module. The G2 ships no strings.

      

      

        
⌬

        
Override on glasses

        
Change it from the phone page (Language) or the glasses shortcuts menu (Lingua). Selection is device-local: it never modifies the world setting. Auto mode follows Foundry; an explicit override sticks per device.

      

      

        
▤

        
Width-budget by key

        
Every i18n key carries a _max width. The build verifies all locales fit, otherwise falls back to English. Layout integrity (INV-1) holds even when Italian strings run 30% longer than English.

    ≣ voice · future
    
🎙️ Voice: removed in v0.12.0, may return.

    
The bridge-hosted Deepgram proxy and the foundry-mcp server were removed together with the bridge (ADR-0016). The product is fully usable with gestures alone. Voice or MCP control may come back later as a client of the same direct channel — that needs a new ADR.

    

      

        
⌬

        
Mic capture: hardware-feasible

        
The G2 4-mic array streams PCM 16 kHz to plugins through the Even Hub SDK. Not used since v0.12.0. §3.5

      

      

        
⊟

        
AI on-glasses: not possible

        
EvenAI is proprietary, cloud-backed, and exposes no API to developer apps. Any future voice path must be external. §3.6

      

      

        
▤

        
No speaker → visual feedback only

        
The G2 has no audio output. Every result lands as a toast or a HUD update — never a beep, never a TTS line.
